# Онлайн-запись: ошибка получения доступных специалистов

## Проблема

После выбора услуги, даты и времени frontend вызывает endpoint доступных специалистов. Endpoint возвращает `500`, поэтому пользователь не может перейти к выбору специалиста.

React Query раньше автоматически повторял запрос несколько раз, из-за чего пользователь долго видел сообщение `Проверяем специалистов...`.

## Воспроизведение

```http
GET /public-api/booking/branches/19/availability/2026-06-11/employees?services=99&time=09:00
```

Проверено также на нескольких других датах и свободных слотах филиала `19`. Endpoint свободного времени возвращает эти слоты, но endpoint специалистов для них возвращает `500`.

## Фактический ответ

```json
{
  "success": false,
  "name": "PHP Warning",
  "message": "Undefined variable $totalDuration",
  "type": "yii\\base\\ErrorException",
  "file": "/www/wwwroot/api.hahazen.com/services/AvailabilityService.php",
  "line": 117
}
```

## Причина

В `AvailabilityService::getAvailableEmployees()` используется переменная `$totalDuration`, которая не была определена до строки `117`.

## Что исправить на backend

1. До использования вычислить и определить `$totalDuration` для переданных услуг.
2. Проверить, что все переданные `service_id` существуют и доступны для онлайн-записи в указанном филиале.
3. Вернуть доступных специалистов, работающих в выбранный слот и выполняющих все выбранные услуги.
4. Если специалистов нет, вернуть успешный ответ с пустым массивом, а не `500`.
5. Если входные параметры некорректны, вернуть `422` с понятным сообщением.
6. В production не возвращать клиенту stack trace и абсолютные пути файлов.

## Ожидаемый ответ

Если специалисты есть:

```json
{
  "data": [
    {
      "id": 12,
      "name": "Анна",
      "specialization": "Массажист"
    }
  ]
}
```

Если специалистов нет:

```json
{
  "data": []
}
```

## Frontend mitigation

На frontend отключены автоматические повторы этого запроса и добавлена кнопка `Проверить ещё раз`. Это убирает долгое зависание, но полноценный выбор специалиста заработает только после исправления backend.

## Acceptance criteria

- Endpoint не возвращает `500` из-за неопределённой `$totalDuration`.
- Для существующего свободного слота и подходящего специалиста возвращается специалист.
- При отсутствии специалистов возвращается `200` и пустой массив.
- Некорректные параметры возвращают `422`.
- Публичный production API не раскрывает stack trace и абсолютные пути файлов.
